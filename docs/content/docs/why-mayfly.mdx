## The Core Problem

Almost every development workspace has a `.env` or `.env.local` file containing production credentials, database passwords, and third-party API keys in plaintext.

When developers run commands like `npm install`, `pip install`, or `cargo build`, untrusted package install scripts execute with full user privileges. In real-world software supply-chain attacks, malicious packages scan local disk trees for `.env` files and exfiltrate secrets before the application even starts.

## Where MayFly Fits

MayFly is built for:
- **Local Development**: Run `mf npm run dev` or `mf python main.py` without leaving credentials on your workstation disk.
- **CI / Build Machines**: Inject build credentials into compilation steps without writing transient env files.
- **Developer Workstations**: Prevent accidental commits of `.env` files into Git repositories.
- **Supply-Chain Hardening**: Mitigate malicious npm/pip lifecycle scripts (`postinstall`) from exfiltrating credentials.

---

## What MayFly Does Not Try to Be

- **A Team Secrets Synchronization Cloud**: MayFly does not sync credentials to third-party cloud servers over the internet. It is strictly a secure local workstation secrets manager.
- **A Secret Rotation Daemon**: MayFly stores, protects, and injects your secrets locally. Automated remote token rotation should be managed via your cloud identity provider.
