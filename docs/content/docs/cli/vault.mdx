## mayfly init

Initialize an encrypted vault container for the current directory.

```bash
mayfly init [-path DIR]
```

---

## mayfly set

Assign or update an encrypted secret variable in the current project vault.

```bash
mayfly set <KEY>
```

### Ephemeral Alt-Screen Entry (Recommended)

When run without a value argument in an interactive terminal, MayFly opens a clean, ephemeral alternate terminal screen:
```
  Enter value for STRIPE_KEY: █
```
- The secret is visible to you for instant visual verification of copy-pastes.
- Pressing `Enter` immediately closes the screen and saves the secret to the encrypted vault.
- Zero traces are left in terminal scroll-back or shell history files (`~/.bash_history` / `~/.zsh_history`).

---

## mayfly get

Retrieve the decrypted value of a secret key.

```bash
mayfly get <KEY> [--clip]
```

### Flags
- `--clip` / `-c`: Copy the secret value directly to your system clipboard (using OSC 52, `pbcopy`, `wl-copy`, or `clip`) without printing plaintext to stdout or terminal scroll-back.

```bash
mayfly get STRIPE_SECRET_KEY --clip
```

---

## mayfly list

List secret keys registered for the current project.

```bash
mayfly list [--json]
```

### Flags
- `--json`: Output secrets as structured JSON array for CI scripts and automation.

---

## mayfly import

Bulk-import existing `.env` files directly into your encrypted project vault.

```bash
mayfly import [.env]
```

Parses standard `.env` formats (handles comments, `export ` prefixes, single and double quotes) and registers all valid secrets into the vault.

---

## mayfly rotate-password

Re-encrypt the entire vault under a new master password with a fresh random salt.

```bash
mayfly rotate-password
```

Prompts for your current master password (with echo suppressed), validates it, and re-encrypts all project credentials in memory before writing to disk.

---

## Automated CI Environments

You can supply the master password non-interactively using the `MAYFLY_VAULT_PASSWORD` environment variable in headless CI pipelines (e.g., GitHub Actions, GitLab CI):

```bash
export MAYFLY_VAULT_PASSWORD="ci-vault-password"
mf npm test
```

<Callout type="warn" title="Desktop Security Notice">
Do not store `MAYFLY_VAULT_PASSWORD` permanently in your shell configuration (`~/.bashrc` / `~/.zshrc`). On Unix systems, environment variables can be inspected by other processes owned by the same user via `/proc/<pid>/environ`. Use interactive prompts for local development.
</Callout>
