## Install

MayFly works on macOS and Linux (including WSL). Pick any method — it ships as a single static binary with zero external dependencies.

<Tabs items={['curl', 'macOS', 'Linux', 'Go Install', 'From Source']}>
  <Tab value="curl">
```bash
curl -fsSL https://raw.githubusercontent.com/vishnunandan555/mayfly/main/install.sh | bash
```
  </Tab>

  <Tab value="macOS">
```bash
# macOS (Intel & Apple Silicon)
curl -fsSL https://raw.githubusercontent.com/vishnunandan555/mayfly/main/install.sh | bash
```
  </Tab>

  <Tab value="Linux">
```bash
# Linux (All distributions & WSL)
curl -fsSL https://raw.githubusercontent.com/vishnunandan555/mayfly/main/install.sh | bash
```
  </Tab>

  <Tab value="Go Install">
```bash
go install mayfly/cmd/mayfly@latest
```
  </Tab>

  <Tab value="From Source">
```bash
git clone https://github.com/vishnunandan555/mayfly.git
cd mayfly
./install.sh
```
  </Tab>
</Tabs>

Verify the installation:

```bash
mf version
# -> mayfly v1.0.0 (zero-dependency)
```

## Your First Sandboxed Command

<Steps>
<Step>

### 1. Initialize the Project Vault

Navigate to your application directory and initialize the encrypted storage:

```bash
cd /path/to/my-project
mf init
```

You will be prompted for a master password. MayFly derives a 256-bit AES key using PBKDF2-HMAC-SHA256 (600,000 iterations) and binds the vault to your hardware directory inode.

</Step>

<Step>

### 2. Store Application Secrets

Add environment variables to the project vault without writing any plaintext `.env` files:

```bash
mf set DATABASE_URL="postgres://user:password@localhost:5432/app"
mf set STRIPE_SECRET_KEY="sk_live_0123456789abcdef"
mf set JWT_SECRET="super-secret-token"
```

To list registered keys for the project:

```bash
mf list
```

</Step>

<Step>

### 3. Run Command with In-Memory Injection

Execute any command directly using `mf` (or `mayfly`):

```bash
# Node.js / Next.js
mf npm run dev

# Python / FastAPI / Django
mf python main.py

# Docker Compose
mf docker compose up -d
```

MayFly resolves the project identity, decrypts secrets into volatile RAM, and spawns the binary via direct `os/exec`. Unencrypted secrets never touch the filesystem.

</Step>

<Step>

### 4. Verify Cryptographic Audit Trail

Confirm that the access event was immutably recorded in the tamper-evident SHA-256 hash chain:

```bash
mf audit verify
# -> Audit log hash chain verified successfully.
```

To inspect full chronological event history:

```bash
mf audit
```

</Step>
</Steps>

<Callout type="info" title="Zero Disk Footprint">
MayFly never writes an unencrypted file to disk. If your application or a third-party dependency inspects the filesystem for a <code>.env</code> file, none exists. Decrypted variables are only accessible in the child process memory table.
</Callout>
